# Multi-Exchange Wall Scanner — состояние проекта

Обновлено: 2026-07-19. Этот файл — чтобы новый чат (или человек) быстро понял,
что уже сделано, не перечитывая всю историю переписки.

## Что это

Desktop-приложение (Python + Tkinter) для поиска "плотностей" (крупных заявок)
и паттернов в стакане на фьючерсах 4+ бирж: Binance, AsterDEX, Gate.io, OKX
(плюс Bybit — только для лёгкого рыночного сканера, без полного стакана).

## Файлы

- `main.py` — точка входа.
- `gui.py` — весь UI (Tkinter), состояние приложения, колбэки от бирж.
- `detector.py` — логика детектора плотностей/стенок/каскадов/магнита.
- `orderbook.py` — локальный стакан на символ (синхронизация по алгоритму Binance).
- `ws_manager.py` — WS-клиент для Binance-style бирж (Binance, AsterDEX).
- `gate_ws.py`, `okx_ws.py` — WS-клиенты Gate.io и OKX (свои протоколы).
- `market_scan.py` — лёгкий REST-опрос всего рынка (без стакана) для вкладок
  "Топ движений" и "Ерши"; здесь же фетчер Bybit.
- `debug_log.py` — файловый лог (`debug.log` рядом с exe).
- `config.json` — список отслеживаемых монет и их настроек (см. схему ниже).
- `sounds/Sound_07.wav` — звук алерта "ПЛОТНОСТЬ" (пользовательский файл).
- `build_exe.bat` — скрипт сборки onedir-версии.
- `tests/` — все тесты этой сессии, перенесены из scratchpad, пути
  относительные (см. раздел "Тесты" ниже).

## Полный список фич (по мере добавления)

1. **Фикс "биржи не подключаются"** — было 2 независимых бага:
   - Гонка потоков + неверный алгоритм ресинка в `orderbook.py` (снапшот vs
     WS-diff) — приводил к бесконечному циклу ресинков и 429 от биржи.
   - Gate.io: бутстрап стакана не перезапускался после сбоя сети.
2. **Диапазон объёма плотности** — поля "от $"/"до $" + пресеты (20-40к,
   40-50к, 100-150к, 150-250к, 250-500к, 500к-1м) + ручной ввод. Пустое
   "до $" = режим "от и выше" (без разницы, насколько крупная).
3. **КАСКАД** (`CASCADE`) — 2+ плотности РАВНОГО объёма (округление до $),
   появившиеся ОДНОВРЕМЕННО (в один тик скана) рядом по цене. Разовый сигнал,
   без задержки/подтверждения (сознательно, по просьбе — спуф отсекается
   равенством объёма, а не таймером).
4. **МАГНИТ** (`MAGNET`) — переделан на "цена реально дошла/пересекла
   уровень" (не просто приблизилась), окно 2–10 сек после появления. В
   алерте показывается объём: сколько осталось / сколько съедено ($ и %).
5. **Одиночная плотность (APPEARED)** — алерт только после
   `single_confirm_sec` (10 сек) непрерывной стабильности. Если пропала
   раньше — вообще без алерта (антиспуф). EATEN/PULLED — только для уже
   подтверждённых.
6. **СТЕНКА (WALL/WALL_GONE)** — дважды переработана:
   - Сначала: строгое равенство объёма участников (округление до $).
   - Потом ослаблено до допуска `wall_volume_tolerance_usd` = **$30,000**
     (весь разброс max-min внутри группы, не "по цепочке соседей" — иначе
     цепочка 10к→20к→30к→... расползлась бы сколь угодно широко).
   - Добавлена устойчивость: кандидаты должны непрерывно простоять
     `single_confirm_sec` (свой отдельный таймер `wall_candidate_seen`,
     радиус поиска остался широким `wall_max_distance_pct`=15%, не сузили).
7. **Baseline-фильтр** — то, что уже было в стакане на САМОМ ПЕРВОМ скане
   после запуска/добавления символа (`is_baseline_tick` /
   `WallState.is_baseline`), НИКОГДА не даёт алертов (ни появление, ни
   магнит, ни съедено/снято). То же самое для стенок (`known_clusters[].baseline`,
   наследуется по overlap из тика в тик, пока кластер физически жив).
8. **Дистанция видимости плотности** (`max_distance_pct`) — раньше жёстко
   3%, потом 10% глобально, **теперь настраивается по каждой монете
   отдельно** через поле в UI (дефолт 10, сбрасывается после каждого
   добавления, не "липкое").
9. **"Топ движений"** (вкладка) — топ-20 роста/падения за 24ч по всем 4
   биржам + импульс за 3 мин (`market_scan.py`, лёгкий REST-опрос всего
   рынка одним запросом на биржу, БЕЗ снапшотов по символам — не грузит
   rate-лимиты). Двойной клик — добавляет монету в сканер (режим AUTO).
10. **"🦔 Ерши"** (вкладка) — поиск узкого бокового диапазона на низком
    объёме (паттерн "лесенка"/hedgehog). Только **Binance + Bybit** (по
    просьбе). Считается из той же скользящей истории тикеров, окно 90 мин.
    Колонки: диапазон %, touch верх/низ, объём 60м/10м.
11. **"🌐 ВСЕ БИРЖИ"** — пункт в комбобоксе "Биржа": один тикер + один клик
    добавляет монету на все 4 биржи, где она реально торгуется (проверка
    через `validate_symbol` в фоне), молча пропуская остальные.
12. **Экспорт/импорт конфига** — кнопки "💾 Экспорт конфига" / "📂 Импорт
    конфига", файловые диалоги. Импорт ДОБАВЛЯЕТ к текущему списку, не
    стирает. Для переноса настроек между версиями приложения.
13. **Копирование тикера в буфер** — двойной клик в ЛЮБОЙ таблице, где
    показан символ (сканер, активные плотности, лента алертов, топ
    движений, ерши), копирует тикер в буфер обмена (для вставки в торговый
    терминал). Не ломает старое поведение (редактирование / добавление в
    сканер по двойному клику — работает и то, и другое).
14. **UI/эстетика** — тёмная почти-чёрная палитра (не навy-синяя), зелёный/
    красный для BID/ASK, лента алертов как таблица с колонками (не одна
    строка), стабильный порядок строк в "Активные плотности" (по очерёдности
    обнаружения, не "прыгает" при обновлении других монет), звук
    `Sound_07.wav` на алерт ПЛОТНОСТЬ (остальные события — синтезированный
    мягкий колокольчик вместо резкого `winsound.Beep`).
15. **Standalone build** — `--onefile` сборка (`BinanceWallScanner-Standalone.exe`)
    для передачи другу одним файлом, отдельно от обычной `--onedir` версии.

## Схема config.json (на символ)

```json
{
  "exchange": "BINANCE",
  "symbol": "LABUSDT",
  "mode": "FIXED",                 // или "AUTO"
  "threshold": 100000.0,           // "от $"
  "threshold_max": null,           // "до $", null = "от и выше"
  "direction": "LONG",             // LONG/SHORT/BOTH
  "muted": false,
  "max_distance_pct": 10.0         // дистанция видимости, per-symbol
}
```
Поля `threshold_max`/`max_distance_pct` отсутствуют в СТАРЫХ конфигах —
обратная совместимость есть (дефолты подставляются автоматически).

## КАК ПЕРЕСОБИРАТЬ .exe (важные грабли)

1. **Приложение должно быть закрыто** — Windows блокирует файлы запущенного
   exe, пересборка падает с `PermissionError`. Проверять:
   `Get-Process BinanceWallScanner -ErrorAction SilentlyContinue`.
2. **PyInstaller ПОЛНОСТЬЮ УДАЛЯЕТ папку `dist/BinanceWallScanner/` при
   каждой пересборке**, включая живой `config.json` пользователя! Порядок:
   - `cp dist/BinanceWallScanner/config.json` → бэкап во временную папку
   - пересобрать
   - скопировать бэкап обратно в `dist/BinanceWallScanner/config.json`
3. **Звук не подхватится автоматически** — обязательно передавать
   `--add-data "sounds;sounds"` в команде сборки, иначе `sounds/Sound_07.wav`
   не попадёт в exe (fallback на синтезированный тон сработает, но
   пользовательский звук пропадёт молча).
4. Полная команда (onedir, обычная версия):
   ```
   python -m PyInstaller --onedir --windowed --noconfirm --name BinanceWallScanner --add-data "sounds;sounds" main.py
   ```
5. Standalone (для передачи другу, отдельное имя — не мешает обычной сборке):
   ```
   python -m PyInstaller --onefile --windowed --noconfirm --name BinanceWallScanner-Standalone --add-data "sounds;sounds" main.py
   ```
6. Первый запуск свежего exe может занять ~1-2 минуты — Windows Defender
   сканирует неподписанный файл. Это не баг, при повторных запусках быстро.

## Тесты (`tests/`)

21 файл, независимые друг от друга, каждый использует **временный**
`CONFIG_FILE` (не трогают боевой `config.json`). Запуск:
```
cd tests
python test_ИМЯ.py
```
Покрывают: каскад, диапазон объёма, магнит+подтверждение, baseline-фильтр
(и для плотностей, и для стенок), равный объём/допуск/устойчивость стенки,
объём в алерте магнита, ерши (математика + живой Bybit), топ движений (GUI +
живые данные всех бирж), "все биржи" (контролируемо + живая сеть), стабильный
порядок в "Активные плотности", звук, per-symbol дистанция, экспорт/импорт
конфига, копирование в буфер.

Несколько тестов (`*_live.py`) бьют по реальным REST-эндпоинтам бирж — не
mock, честная проверка на живых данных.
