# Multi-Exchange Wall Scanner (MVP)

Десктопное приложение для детекта крупных заявок (плотностей) в стакане
фьючерсов и spot-рынков в реальном времени. Поддержаны **Binance**,
**AsterDEX**, **Gate.io**, **OKX**, **MEXC** и отдельный рынок
**Binance Alpha**. Futures/swap и spot выбираются отдельными строками в поле
`Биржа`, например `BINANCE` и `BINANCE SPOT`.

## С чего начинать работу над проектом

Если ты не программируешь руками, открывай эти файлы:

- `WORKFLOW.md` — как ставить задачи Codex/коллеге и работать через GitHub.
- `RELEASE_CHECKLIST.md` — что проверить перед выдачей новой версии.
- `CHANGELOG.md` — что менялось по датам.
- `BUGS.md` — куда записывать ошибки и наблюдения.
- `DEBUG_PACK.md` — как собрать архив для диагностики.
- `PROJECT_NOTES.md` — подробная техническая память проекта для нового чата.

Для сборки готового приложения можно запускать:

```bat
build.bat
```

## Установка и запуск

Нужен Python 3.9+.

```bash
pip install -r requirements.txt
python main.py
```

На Windows, если `python` не находит tkinter — переустанови Python с
официального сайта python.org, поставив галку "tcl/tk and IDLE"
(в стандартной установке это есть по умолчанию).

## Собрать .exe (Windows) — чтобы не лезть в cmd каждый раз

Собрать exe можно только на самой Windows-машине — кросс-сборка Windows-exe
из Linux для таких приложений не работает надёжно, поэтому сделать это за
тебя я не могу, но сделал сборку максимально простой:

1. Открой cmd/PowerShell в папке проекта (там же, где `main.py`)
2. Запусти:
   ```
   build.bat
   ```
3. Подожди — скрипт сам поставит зависимости, закроет старый запущенный exe,
   сохранит конфиги, соберёт приложение и вернёт конфиги на место.
4. Готовые файлы появятся здесь:
   - `dist\BinanceWallScanner\BinanceWallScanner.exe`
   - `dist\BinanceWallScanner-Standalone.exe`

Дальше просто копируй **всю папку** `dist\BinanceWallScanner` куда угодно
(например на Рабочий стол) и делай ярлык на `.exe` внутри неё — двойной
клик, никакого cmd.

**Почему есть две версии**:

- `dist\BinanceWallScanner\BinanceWallScanner.exe` — обычная папочная версия,
  быстрее стартует и удобнее для ежедневной работы.
- `dist\BinanceWallScanner-Standalone.exe` — один файл, удобно отправить другу,
  но первый запуск может быть дольше из-за проверки Windows Defender.

Конфиг (`config.json`) при первом запуске экзешника копируется из текущей
папки проекта автоматически, если он там есть, — дальше живёт рядом с
собранным `.exe` и сохраняется между запусками как обычно.

## Как пользоваться

1. Выбери **Биржу** (`BINANCE`, `BINANCE SPOT`, `MEXC`, `MEXC SPOT` и т.д.).
   Futures/swap и spot добавляются отдельно. Если нужно проверить сразу все рынки,
   выбери пункт **🌐 ВСЕ БИРЖИ**.
2. В поле **Символ** впиши тикер. На обычных рынках можно писать без `USDT`:
   `lab` превратится в `LABUSDT`. Для `BINANCE ALPHA` можно писать привычный
   тикер токена, например `CAP`; программа сама найдёт нужный `ALPHA_...USDT`.
3. Под полем **Символ** появляется автодополнение по известным тикерам.
4. Тикеры внутри приложения хранятся в формате Binance (`LABUSDT`) — конвертация
   в формат конкретной биржи (`LAB_USDT` у Gate, `LAB-USDT-SWAP` у OKX)
   происходит автоматически внутри приложения.
5. **Порог/пол $** — минимальный размер заявки в долларах.
6. **Режим**: `FIXED` (число как есть) или `AUTO` (само-калибровка, см. ниже).
7. Направление не выбирается вручную: сканер всегда смотрит обе стороны (`BOTH`).
8. Жми **Добавить**. Двойной клик по строке — подставляет её значения в поля
   для редактирования.
9. **Старт** — подключение сразу ко всем биржам из списка монет.

Один и тот же тикер можно добавить на нескольких биржах разом через пункт
**🌐 ВСЕ БИРЖИ** в списке бирж — это будут независимые строки, каждая со
своим порогом. Spot-строки подписаны прямо в колонке "Биржа":
например `BINANCE SPOT`.

Конфиг сохраняется в `config.json` рядом с программой. Старые записи без
поля `exchange`/`mode` читаются нормально (считаются Binance/FIXED).

## Быстрые действия

- Правая кнопка мыши по строке любой таблицы копирует чистый тикер.
- `Ctrl+C` копирует тикер из выделенной строки активной таблицы; работает и на английской, и на русской раскладке.
- `Del` / `Num Del` удаляет все выделенные монеты из таблицы сканера.

## Что означают алерты

| Метка | Что произошло |
|---|---|
| 🟨 ПЛОТНОСТЬ | Появилась одиночная заявка крупнее порога на одном уровне цены |
| 🧱 СТЕНКА | Несколько (3+) плотностей рядом друг с другом — самостоятельный сигнал, идёт **вместе** с отдельными 🟨, не вместо них |
| 🧱💨 РАССЕЯЛАСЬ | Стенка перестала существовать (просела ниже порога участников) |
| 🟧 МАГНИТ | Цена реально подошла близко к плотности в течение нескольких секунд после её появления (см. ниже) |
| 🟩 ПРОЕЛИ | Плотность исчезла, и цена прошла сквозь её уровень — вероятно, исполнена рынком. На Binance/Binance Spot дополнительно показываются найденные принты по уровню |
| 🟥 СНЯЛИ | Плотность резко похудела/исчезла, а цена до неё не дошла — вероятно, отменена (спуф). Без принтов по уровню скринер больше не добавляет отдельную догадку |

Дополнительно к размеру плотности показывается метка масштаба:
🟡 мелкая / 🟠 средняя / 🔴 крупная / 🐋 огромная (пороги: 200K / 500K / 1M).

### Стенка vs одиночная плотность

Стенка = **3 и более** заявок на соседних уровнях цены (зазор между
соседними не больше **0.15%** от цены). Меньше трёх — это просто одиночная
плотность, отдельного 🧱-сигнала не будет, только обычная 🟨.

Оба числа — `wall_min_components` (сейчас 3) и `wall_cluster_gap_pct`
(сейчас 0.15) — задаются в `detector.py`, в `SymbolConfig`. Индивидуальные
🟨-алерты по каждому уровню продолжают идти даже если они вошли в состав
стенки — сейчас это дополнительный сигнал сверху, а не замена. Если
окажется что это слишком шумно (видишь и 3 отдельных 🟨, и потом ещё 🧱) —
скажи, добавлю подавление одиночных при формировании стенки.

Из коробки трек магнита/поглощения/снятия делается **по каждому уровню
отдельно**, даже если он часть стенки — то есть если стенка из 4 плотностей
частично проедается, ты увидишь 🟩 по конкретному съеденному уровню, а не
по стенке целиком. Отслеживание этих событий именно для стенки как единого
целого — возможное следующее улучшение.

### Как считается МАГНИТ

Через **magnet_window_min_sec–magnet_window_max_sec секунд** (сейчас 1–10с)
после появления плотности проверяется: подошла ли цена ближе чем на
**magnet_distance_pct %** (сейчас 0.5%) к её уровню. Если да — алерт,
проверка на этом для данной плотности заканчивается. Если окно (10с)
закрылось, а цена так и не подошла — магнит для этой плотности уже не
сработает.

Три параметра — `magnet_window_min_sec`, `magnet_window_max_sec`,
`magnet_distance_pct` — в `detector.py`, конструктор `SymbolConfig`.

### Звуковые алерты

Чекбокс **🔔 Звук** — вкл/выкл глобально. У каждого типа события свой тон
(на Windows через `winsound`; на Mac/Linux — обычный терминальный "звонок",
не тестировалось).

### Панель "Активные плотности"

Живая таблица под списком монет: сторона, цена, размер $, возраст
(до минуты с десятыми долями секунды, дальше мм:сс), дистанция от текущей
цены в %. Обновляется раз в секунду.

### Повторяющиеся принты

Нижняя область сканера теперь переключается между вкладками **Повторяющиеся принты** и
**Активные плотности**. Принты строятся по Binance/Binance Spot raw `trade` и показывают
серии из минимум 3 рыночных сделок одной стороны с похожим долларовым объёмом.

- **От $ / До $** — фильтр долларового размера одного принта. Пустое `До $`
  означает “от указанного объёма и выше”.
- **Окно, с** — сколько секунд назад смотреть принты. `0` означает строгий режим “идут подряд”.
- **Похожесть, %** — допустимое отличие объёма от последнего принта серии. По умолчанию `15`.

## Режим порога: FIXED vs AUTO

**FIXED** — число в "Порог/пол $" используется как есть.

**AUTO** — порог = медиана размера уровня в этом же стакане (без уже-стенок
и без уровней дальше `max_distance_pct`) × **8**, но не ниже "Порог/пол $"
(тут оно работает как пол). Так одна и та же монета на разных биржах с
разной ликвидностью получает разный порог в $ автоматически.

**Прогрев**: минимум 30 наблюдений прежде чем AUTO начнёт искать плотности —
колонка "Тек. порог $" покажет "прогрев...", обычно проходит за секунды.

## Фильтр по дистанции от спреда

Уровни дальше выбранной **Дистанции %** (`max_distance_pct`) от края спреда
игнорируются. Если ввести `0`, приложение использует минимальный практический
радиус `0.01%`, чтобы ловить плотности прямо у спреда.

Поле **Жизнь, с** задаёт, сколько плотность должна простоять до обычного
алерта `ПЛОТНОСТЬ`. Если ввести `0`, алерт приходит сразу на первом
подходящем скане. Время в алертах считается с момента, когда сканер сам
впервые увидел уровень; биржа не присылает отдельное время постановки лимитной
заявки.

## Аудит точности плотностей

Кнопка **Аудит CSV** включает запись диагностического файла рядом с программой:

```text
audit_logs\wall_audit_ГГГГММДД_ЧЧММСС.csv
```

Файл нужен для сверки с Tiger/другим терминалом. В него пишутся:

- `EVENT` — алерты сканера: появление, под спредом, магнит, сняли, проели, стенка.
- `ACTIVE` — текущие активные плотности на каждом обновлении стакана, пока аудит включён.

В строках есть время с миллисекундами, биржа, spot/futures, символ, сторона,
цена, размер в монетах, размер в $, best bid/ask, спред, расстояние от спреда,
возраст плотности, применённые фильтры и, для Binance/Binance Spot, сводка принтов
по цене плотности. Когда включён аудит, отдельные строки `TRADE` пишут сырые
trade-сделки Binance: цена, количество, долларовый объём и агрессивная сторона
`buy`/`sell`. Папка `audit_logs` игнорируется Git,
чтобы большие проверочные файлы случайно не отправлялись в репозиторий.

Для сверки со стаканом Tiger добавлен экспериментальный кастомный индикатор
`tiger_dom_logger\TigerDomLogger.cs`. Инструкция по установке лежит рядом:
`tiger_dom_logger\README.md`.

## Биржи

| Биржа | Протокол | REST-снапшот нужен? | Символы |
|---|---|---|---|
| Binance / Binance Spot | родной / Binance-style spot | да (`/fapi/v1/depth`, `/api/v3/depth`) | `LABUSDT` |
| AsterDEX / AsterDEX Spot | клон Binance | да (`/fapi/v1/depth`, `/api/v1/depth`) | `LABUSDT` |
| Gate.io | свой (`futures.order_book_update`) | да, с `with_id=true` | `LAB_USDT` (конвертится автоматически) |
| Gate.io Spot | свой (`spot.order_book_update`) | да, с `with_id=true` | `LAB_USDT` (конвертится автоматически) |
| OKX / OKX Spot | свой (`books`) | **нет** — снапшот приходит через WS | `LAB-USDT-SWAP` / `LAB-USDT` (конвертится автоматически) |
| MEXC / MEXC Spot | REST-опрос стакана | каждый тик — полный снапшот | `LAB_USDT` для futures, `LABUSDT` для spot |
| Binance Alpha | REST `fullDepth` | каждый тик — полный снапшот | можно вводить обычный тикер, внутри используется `ALPHA_...USDT` |

**Про AsterDEX**: протокол подтверждён документацией как клон Binance один
в один, но точный путь комбинированного стрима (`/stream?streams=...`) я
не мог проверить вживую (нет сети в моей среде) — если он не подключается,
статус внизу покажет причину, напиши что там написано.

**Про Gate/OKX**: получены из официальной документации, но тоже не
протестированы вживую по той же причине. Если тикер не находится или
подключение обрывается — статус-бар покажет ошибку, это самое полезное,
что можно прислать для диагностики.

**Про MEXC/Binance Alpha**: это первые версии подключения через REST-опрос
стакана, а не WebSocket. Для MEXC futures объём контрактов пересчитывается
через `contractSize`. Для Binance Alpha можно использовать обычные тикеры из
автодополнения (`CAP`, `DATAIP` и т.п.); внутри они переводятся в `ALPHA_...USDT`.

## Известные ограничения

- **EATEN vs PULLED** для Binance/Binance Spot дополнительно получает факты из
  raw `trade`: если по цене плотности прошёл встречный рыночный объём, в деталях
  показывается сумма и количество принтов по уровню. Если принтов по уровню нет,
  отдельная текстовая догадка не добавляется. Для AsterDEX/Gate/OKX пока остаётся
  эвристика по стакану и движению цены.
- Символ `龙虾USDT` (иероглифы) в конфиге на Binance — работоспособность
  не подтверждена вживую, см. статус-бар при добавлении.
- Bitget из более раннего роадмапа пока не подключён.
